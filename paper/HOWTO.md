# 模拟盘说明

6 个策略各有一个独立的 **10 万元**模拟账户，由 GitHub Actions 在每个交易日**北京时间 18:47** 自动运行，按 `signal` 工具确定股票和顺序，执行时重新检查状态、余额和名额；股数会重算。

| 账户 | 清单来源 | 成交方式 |
|---|---|---|
| A_top50 / A_top20 / AE_top20 | `strategies/live.py signal` | 下一交易日**收盘价**（尾盘集合竞价）；涨停/停牌买不进按顺序用替补；跌停/停牌卖不出就继续持有，第二天的清单会再卖 |
| C_top50 | `strategies2/live.py signal` | 同上 |
| K_top3 | `strategies2/live.py signal` | 下一交易日**开盘价**，滑点千1；股数按"目标金额 ÷ 开盘价"重新计算；开盘一字涨停/停牌用替补 |
| FB_dip | `strategies2/fb_live.py signal` | 开盘价筛选低开2%–7%，09:35首5分钟价加滑点近似买入，限价开盘价+0.5%；缺价/超限价不买，最多2只；次日收盘卖出，跌停/停牌顺延 |

**R3 风控**（A/C 系列）：连续未控仓参考账户相对指数净值从高点回撤触发。先用现金，再按所需金额卖股票购买ETF；解除时实际卖出ETF。状态与参考账户逐日保存，不滚动重置。ETF 没有单独的价格数据，用中证1000 指数的日收益近似。

**费用**：A/C/K 按各自 config（买万5，卖佣金和印花税分别计；最低5元只用于佣金）；FB_dip 按研究口径（佣金万2.5、印花税万5、单边滑点千1）。

## 每天发生了什么

每次运行对每个还没处理的交易日 d 依次执行：

1. **成交**：执行上一交易日生成的清单，价格使用对应执行时点的报价近似，FB使用独立09:35报价
2. **盯市**：K/FB开盘操作先按开盘价估值并除权折算，所有账户最终按d日收盘价估值（除权除息用复权因子把股数折算，相当于分红再投资，所以除权后股数可能带小数；复权因子变化小于 0.3% 的小额分红忽略）
3. **出清单**：用账户当前的真实持仓和现金调用策略的 `signal` 工具，生成 d+1 的清单

社区 Qlib 数据包只提供历史底座，当前交易日日线与 ST/停牌状态直接从 Baostock 获取。用独立交易日历确定应有的数据日期；所有当前成分股、持仓和基准验证通过后才更新日历并开始账户处理。

北京时间 18:47 主任务，20:17、22:47 重试。数据缺失、日期落后、状态未知或复权衔接失败均明确报错，不能以“账户已是最新”成功退出。GitHub 定时任务可能排队，以上是计划触发时间。

历史底座仍使用原模型训练时的数据和 Qlib 格式，避免直接换成未复权行情改变模型输入；新增价格按涨跌幅复权并校验重叠日期，成交量/成交额保留历史单位。当前成分延续历史底座的最新成员，定期成分调整仍需底座更新。

## 常用操作

- **手动运行**：GitHub 仓库 → Actions → "模拟盘每日运行" → Run workflow（勾选 force 会强制重跑）
- **重置某个账户**：删除 `paper/accounts/<策略>/` 目录并提交，下次运行会以 10 万元重新开始
- **改初始资金**：在 workflow 的 `env` 里加 `PAPER_CASH: 200000`（只对新建的账户生效）
- **本地运行**：`bash setup_env.sh && source env.sh && pip install baostock && bash paper/run_daily.sh`

## 需要知道的

- **10 万元对 A_top50 / C_top50 偏小**：50 只等权，每只约 1,900 元，股价高于约 19–28 元的股票买不起一手，清单会标"资金不足一手，用替补"。这会让持仓偏向低价股，和策略 README 里 100 万的回测有差距（策略 README 建议 50 万–300 万）。
- **K_top3 最近一年表现差**：策略 README 第 2 节写过，实盘模型的一年模拟盘是 −20.8%，这个账户很可能继续亏，属于预期内。
- 模拟盘按开盘价/收盘价成交，没有计入冲击成本和排队成交失败，实盘会更差。
- 仅供学习研究，不构成投资建议。
